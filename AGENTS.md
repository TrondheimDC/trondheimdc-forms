# TrondheimDC Forms

TrondheimDC's own front end for Nextcloud Forms: feedback, sign-ups and surveys, in TDC's look. Live at https://forms.trondheimdc.no.

## Public repo

This repo is public. Nothing secret goes in it, not even briefly: git history keeps everything.

- **Secrets:** none while the login is parked. With it on, the OAuth client secret lives only in the nginx config on the server, never in git. Never paste a secret into docs, scripts, tests or commit messages; use placeholders (`cloud.example.org`, `AT1`).
- **Public on purpose:** `nextcloudUrl` and `oauthClientId` (`forms.config.ts`; both end up in the JS bundle anyway) and the share hashes in `forms.config.ts`. A public share hash lets anyone answer that form, so only list forms that are meant to be public. Form hashes of logged-in-only forms are safe to list: they still need a login.
- **No people's data:** no real names, emails or form answers in tests, fixtures or screenshots. The sample form and tests use made-up content.
- Sign-off notes and other internal notes go in `TODO.local.md`, which is git-ignored.

## Architecture

- **Static site.** Next.js App Router with `output: "export"`, served by nginx (`docs/nginx-forms.trondheimdc.no.conf`, `docs/deploy.md`). No app server, and no user credentials anywhere but the visitor's own browser tab. With the login on, the one secret is the OAuth client's, in a root-only nginx include on the server: not in git, not in CI, not in the JS. Parked, there is none.
- **No front page.** `/` is a 404, on purpose: forms are reached by their own link, nothing public lists them.
- **One URL for every form: `/s/{hash}`**, the hash from either kind of Nextcloud link. First tried as a public share hash (`/apps/forms/s/{hash}`), anonymously. If Nextcloud doesn't know it as one, as the form's own hash (`/apps/forms/{hash}`), which needs a logged-in user (`src/lib/load.ts`). `/{slug}` are short names for some of them, from `forms.config.ts`.
- **"Log in with Nextcloud" is parked.** `login: false` in `forms.config.ts` (`LOGIN_ENABLED` in `src/lib/config.ts`): no login button, `/admin` and `/auth/callback` show the not-found page, a members-only form shows a button to answer it in Nextcloud, and nginx forwards only the share page and the Forms API, so the token endpoint and the logged-in-only Nextcloud paths aren't forwarded and the server needs no client secret (the login's locations were in `nginx/forms-login.conf`, in git history). The code below stays, so it can be turned on again (`docs/deploy.md`), but dev has nothing that adds the client secret any more. It was parked because Nextcloud's OAuth app has no PKCE and its tokens have no scopes; the better fix is likely a BFF (nginx + oauth2-proxy), not more browser code.
- **`/admin`** (parked with the login) lists the forms the logged-in user owns or was given (the Forms API has no instance-wide list, not even for admins), as a cmdk palette: Enter copies the link to share, public if the form has a public link, else the members-only one (`src/lib/admin.ts`).
- **Forms load in the browser, on every visit**, so edits in Nextcloud show up on the next page load, with no rebuild. Fetching goes through [React Query](https://tanstack.com/query) (`src/app/providers.tsx`): a new client per page load, and nothing refetches by itself while a form is being filled in.
  - Public forms: Nextcloud has no API to read a form anonymously, so `src/lib/share-page.ts` reads it out of the share page, where Forms puts it as initial state for its own app (`FormsService::getPublicForm()`, already stripped of owner, shares and access settings).
  - Logged-in forms: the Forms app page (`/apps/forms/{hash}`) gives the id, then `GET /api/v3/forms/{id}`.
  - **Both pages are Nextcloud's bootstrap, not its documented API.** If a Forms upgrade breaks loading, start at `src/lib/share-page.ts` and `test/share-page.test.ts`; the console says what didn't fit.
- **Everything from outside is parsed with [Zod](https://zod.dev)**, never cast: the form (`rawFormSchema` in `src/lib/forms.ts`), API answers (`src/lib/ocs.ts`), uploads, the token and pending login in `sessionStorage`, and saved drafts. The types come from the schemas, defaults included (`Question` and `PublicForm` are what the schemas give, not types written alongside them), and no `as` casts. Zod is imported through `src/lib/zod.ts`, which turns off its `new Function` speed-up before any schema is built: the CSP has no `'unsafe-eval'` and would report it on every page load. A form that doesn't fit is unreadable, not half rendered; an unknown question type still parses (for the link to Nextcloud), and a setting that can't be read is dropped, since Nextcloud checks it on submit anyway.
- **Submitting** is the documented `POST /ocs/v2.php/apps/forms/api/v3/forms/{id}/submissions`: with the share hash for a public form, as the logged-in user when there is one (`src/lib/submit.ts`).
- **Logging in happens in the browser** (`src/lib/session.ts`, tested in `test/session.test.ts`), with [`oauth4webapi`](https://github.com/panva/oauth4webapi) for the OAuth protocol: no hand-written state checks or token parsing. OAuth2 against Nextcloud's own OAuth app, code back to `/auth/callback`, tokens in `sessionStorage` (gone with the tab). Nextcloud has no PKCE and wants the client secret on the token request, so that request goes to `/oauth/token` here, where nginx adds the secret.
- **Nextcloud tokens have no scopes**: they can do anything the user can, files included. So: no third-party scripts, no raw HTML from forms (Markdown only, escaped), keep the CSP tight, and only send the token to the Forms paths nginx forwards.
- **Same origin.** The browser only talks to this site; nginx forwards the Nextcloud paths. No CORS, CSP stays `connect-src 'self'`. Nextcloud's HTML comes back sandboxed, and its cookies stay off this site. The site's own requests send `OCS-APIRequest: true`, which Nextcloud wants for its API.
- **`pnpm dev` is plain `next dev`.** The dev branch of `next.config.ts` skips the export and rewrites what nginx forwards: `/s/{hash}`, the share page, submitting and uploading. A new Nextcloud path needs both.
- **Status screens.** Every dead end and end state (404, errors, closed, log in, no access, sent) is a `StatusScreen` with a drawing from `src/components/illustrations.tsx`, after checkin's error screens.
- **Question types.** `src/lib/forms.ts` lists what is rendered (`SUPPORTED_TYPES`), and each has its file in `src/questions` (a family shares one): what its field holds (a Zod schema, also for restoring drafts), the answer Nextcloud gets (a Zod transform, `undefined` while unanswered), Forms' rules for that answer (Zod checks, each with its message), and its `Field`. `src/questions/index.ts` lists them and builds the form's schema; adding a type is a file and a line there. A form with any other type (one Forms adds later) shows a link to the same form in Nextcloud instead of half a form.
- **The form is [React Hook Form](https://react-hook-form.com)**, one field per question (`q{id}`), with a Zod resolver from `formSchema()` in `src/questions/index.ts`: each field in, Nextcloud's answer out, so `handleSubmit` hands over the submission. Plain inputs are `register()`ed, with `deps` on the question where it has several inputs (its problem is the question's, not an input's); choices, ranking, grid, files and colour use `useField(name, schema)` in `src/questions/kind.ts`, a `useController` typed by the field's own value schema: React Hook Form can't type a field whose name comes from Nextcloud, so that is the one place its value is taken for a type (a colour input is never empty, so `register()` would take its black for an answer). Submitting and uploading are React Query mutations. Typing doesn't re-render the form: a question's card (`src/components/Question.tsx`) renders when it starts or stops being done or its problem changes, the progress and problem count subscribe to what they show, and `FeedbackForm` reads neither the answers nor `formState` while rendering. Keep it that way: one `watch()` there renders every question on every keystroke. A new round of answering ("Start over", "Send another answer") is a new form, by `key`.
- **Validation** mirrors `SubmissionService::validateSubmission()` in nextcloud/forms (each type's `rules` in `src/questions`, required in `index.ts`, PHP's own checks in `src/lib/answers.ts`), so Nextcloud only rejects what the browser couldn't know. Its message is shown as-is when it does.
- **Filling in.** Problems show once a question is left (unanswered required ones only after a try at submitting) and clear as soon as they're fixed: every answer is checked as it changes (`mode: "onChange"`), and the question's card decides when to say so. Submitting with problems focuses the first and shakes the cards. Enter in a one-line field goes to the next one in the same question (a range's "To", a grid's next cell), then to the next question. Nextcloud takes any number of answers through a public link (it shows "multiple responses" locked on, but stores false; `fromNextcloud()` reads it the way Forms does), so a named form with `oneAnswer: true` is held to one per browser, in `localStorage`. Answers being written are kept in `sessionStorage` (`tdc-forms:draft:{id}`), not `localStorage`, so the next person on a shared machine doesn't find them; each question takes its field back only if it still fits its type.
- **Motion.** CSS for most of it (`.form-*`, `.choice-*`, `.confetti` in `globals.css`); [`motion`](https://motion.dev) only for the ranking's drag and heights that animate to `auto`. Both follow `prefers-reduced-motion`.
- **English only.** The site's own text is English, in `src/copy.ts`. Nextcloud Forms has no translations (nextcloud/forms#269): a form is in whatever language it was written in, so a second language would only translate the buttons around it.
- **Icons.** `src/app/icon.svg` is the source; `node scripts/build-icons.mjs` renders the favicon, apple icon and manifest icons. `src/lib/og-image.tsx` draws the link previews at build time: the site's at `/og.png`, and one per named form at `/{slug}/og.png` with its title (and `description`, if it has one, from `forms.config.ts`). `/s/{hash}` gets the site's: link previews don't run JavaScript, so its title is never known.

## Copy

- Copy lives in `src/copy.ts`, in English. Write it in TDC's voice, short and plain. No em dashes.

## Design

- Tokens are trondheimdc.no's, as in forening, regnskap and checkin (`src/app/globals.css`). Components use the semantic tokens only.
- The theme is applied before React loads (`next-themes`). Style both themes with the `light:`/`dark:` variants, not by reading the theme in JS.
- Reserve space for anything that appears after hydration. The form itself always loads after it, so `FormLoader` holds the space with a placeholder; the header keeps a slot for the login button.
